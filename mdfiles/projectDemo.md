How to Run Smart DevTool on a Real Project
This is a complete hands-on walkthrough. Copy-paste each command block into your terminal.

Step 0: Activate the tool
Open PowerShell, navigate to the project, and activate the venv:

powershell

cd d:\Project\smartdevtoolv1
.venv\Scripts\Activate.ps1
# Verify it works
python -m smartdevtool.cli --help
You should see all 3 command groups: deps, wrapper, docker.

powershell

# Scan what third-party packages THIS project imports

Option B — Create a sample project with a REAL conflict
powershell

# 1. Make a temp project folder
mkdir C:\Temp\my_sample_project
cd C:\Temp\my_sample_project
# 2. Create a Python file that imports a few packages
@"
import requests
import flask
import sqlalchemy
import pydantic
"@ | Out-File -Encoding utf8 app.py
# 3. Run SmartDevTool to scan and resolve its dependencies
python -m d:\Project\smartdevtoolv1\smartdevtool\cli deps scan .
python -m d:\Project\smartdevtoolv1\smartdevtool\cli deps install . --dry-run --no-llm -y
What the conflict agent actually does
To see it kick in, create a file with a KNOWN conflict:

powershell

# Create a requirements.in with a real version conflict
@"
requests==2.20.0
urllib3==2.0.0
"@ | Out-File -Encoding utf8 requirements.in
python -m smartdevtool.cli deps install . --no-llm -y
You'll see the agent activate:


[!] pip-compile failed with ResolutionImpossible
* Agent Loop [1/8]: [HEURISTIC] Unpinned requests==2.20.0 -> requests (cited 3 times in conflict)
[OK] Conflict resolved on attempt 1 via heuristic!
[OK] Dependencies successfully resolved and installed!
Feature 1 Demo: API Wrapper Generator
Demo 1 — Public GitHub API (no auth needed for public endpoints)
powershell

cd d:\Project\smartdevtoolv1
python -m smartdevtool.cli wrapper `
  --curl "curl -X GET https://api.github.com/repos/python/cpython" `
  --name GitHubRepoAPI `
  --no-validate `
  -y
This generates ./githubrepoapiclient_sdk.py. Open it — it's a complete Python SDK class.

Demo 2 — From a cURL with auth (uses env var, never hardcodes key)
powershell

python -m smartdevtool.cli wrapper `
  --curl "curl -X GET https://api.stripe.com/v1/charges -u sk_test_FAKE123:" `
  --name StripeAPI `
  --no-validate `
  -y
Open the generated file. You'll see the key is stored as:

python

api_key = os.getenv("STRIPE_API_KEY", "")
— never hardcoded.

Demo 3 — From prose documentation (no spec file needed)
powershell

# Write some fake API docs as a text file
@"
# Payment API
Base URL: https://payments.example.com

GET /v1/transactions - List all transactions

Feature 3 Demo: Docker Sync
Pre-requisite: Docker Desktop must be running
powershell

docker info  # If this succeeds, Docker is ready
Step 1 — Generate a Dockerfile for your project
powershell

cd d:\Project\smartdevtoolv1
# First resolve deps so manifest knows what packages you have
python -m smartdevtool.cli deps install . --dry-run --no-llm -y
# Now generate the Dockerfile
python -m smartdevtool.cli docker build . --no-llm -y
A Dockerfile is created. Open it — you'll see:

dockerfile

# Generated by SmartDevTool
FROM python:3.11-slim
WORKDIR /app
# Layer-cache friendly: copy requirements first
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# Then application code
COPY . .
CMD ["python", "main.py"]
Step 2 — Check for drift (without Docker running)
powershell

# Even without Docker, drift detection works offline
python -m smartdevtool.cli docker sync . --no-llm -y
Step 3 — Watch mode (keeps running, rebuilds when you edit files)
powershell

python -m smartdevtool.cli docker sync . --watch --no-llm -y
# Now edit any .py file in the project
# You'll see: "Change detected on yourfile.py. Checking environment drift..."
# Press Ctrl+C to stop
Running on YOUR own existing project
If you have another Python project (e.g., a Flask app, FastAPI service, etc.):

powershell

# 1. Install smartdevtool globally or in the project venv
pip install d:\Project\smartdevtoolv1\dist\smartdevtool-0.1.0-py3-none-any.whl
# 2. Navigate to your project
cd C:\path\to\your\project
# 3. Scan its dependencies
smartdevtool deps scan .
# 4. Resolve and install (dry-run first to be safe)
smartdevtool deps install . --dry-run --no-llm -y
# 5. Generate a wrapper for any API your project calls
smartdevtool wrapper --curl "curl ..." --name MyAPI
# 6. Generate a Dockerfile
smartdevtool docker build . --no-llm -y
Quick Reference: All commands offline (no API key needed)
powershell

# Always works 100% offline — add --no-llm to every command
python -m smartdevtool.cli deps scan .
python -m smartdevtool.cli deps install . --dry-run --no-llm -y
python -m smartdevtool.cli wrapper --curl "curl https://..." --no-validate --no-llm -y
python -m smartdevtool.cli docker build . --no-llm -y
python -m smartdevtool.cli docker sync . --no-llm -y


You never need an API key. --no-llm tells every command to use deterministic logic only. The NVIDIA key only enhances suggestions — without it, everything still works.
